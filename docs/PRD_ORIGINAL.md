# Product Requirements Document
# Nexus — Repo-Scoped AI Toolchain Injection

---

## 1. Overview

### 1.1 Product Name
Nexus

### 1.2 Tagline
Declarative, repo-scoped injection of AI skills, MCP servers, and commands for Claude, Codex, and OpenCode.

### 1.3 Problem Statement

AI developer tools (Claude Code, Codex, OpenCode) each expect configuration and assets in different locations and formats:
- `.claude/skills/`
- `.mcp.json`
- `.codex/config.toml`
- `.opencode/...`

There is no unified way to:
- Compose skills and MCP servers from multiple repositories
- Selectively enable specific tools
- Ensure reproducibility
- Keep configuration repo-scoped
- Avoid wrappers
- Avoid global state
- Avoid machine coupling (e.g., Clan-only)

**We need a clean, declarative, repo-first system.**

---

## 2. Vision

Nexus allows any repository to declare:
- Which AI tools it supports
- Which packs it imports
- Which skills and MCP servers it enables

When entering the repo (via `use flake`), Nexus:
- Injects configuration into the correct locations
- Cleans up stale managed artifacts
- Ensures deterministic, reproducible output
- Requires no wrapper commands

Developers simply run:
```bash
claude
codex
opencode
```

**No sync commands. No global setup.**

---

## 3. Non-Goals

- Nexus is **not** a machine-level provisioning tool.
- Nexus **does not** install Claude/Codex/OpenCode.
- Nexus **does not** depend on Clan.
- Nexus is **not** a runtime wrapper around tools.
- Nexus **does not** manage user global config.

---

## 6. Public API

### 6.1 Entry Point

```nix
nexus.lib.mkRepo {
  system = "x86_64-linux";
  clients = [ "claude" "codex" "opencode" ];
  packs = [ pack-core pack-nix ];
  enable = {
    skills = [ "core:repo-status" ];
    mcp = [ "core:filesystem" ];
  };
  layout = "direct";        # default
  cleanup = "owned-only";   # default
}
```

### 6.2 Activation

```bash
.envrc
use flake
```

Activation occurs via `devShell.shellHook`.

## 7. Pack System

### 7.1 Pack Structure

```
pack.json
skills/<skillId>/SKILL.md
mcp/servers.json
opencode/commands/*.md
hooks/*
commands/*
```

### 7.2 pack.json

```json
{
  "id": "core",
  "version": "1.0.0",
  "imports": []
}
```

### 7.3 Deny-by-default

**Nothing is enabled automatically.**

Everything must be explicitly enabled via `enable`.

---

## 8. Pointer Imports (Pack Composition)

### 8.1 Pointer Schema

```json
{
  "imports": [
    {
      "id": "review",
      "src": "github:someone/skills-pack",
      "rev": "3c1a9e1",
      "path": "skills"
    }
  ]
}
```

### 8.2 Resolution Rules

1. Fetch `(src, rev)` into cache
2. Use only `path`
3. Namespace using: `<packId>/<importId>:<itemId>`

**Example enable:**
```nix
core/review:code-review
```

### 8.3 Safety Rules

- `rev` required (unless explicitly allowed)
- Missing enabled item = error
- Collision = error
- No auto-enable

## 10. Client Emitters

Nexus compiles packs into a **Canonical Graph**, then emits per client.

### 10.1 Claude

**Writes:**
- `.claude/skills/<skill>/`
- `.mcp.json`

**Adds marker:**
```json
"__generated_by": "nexus"
```

### 10.2 Codex

**Writes:**
- `.codex/config.toml`

**Adds header:**
```toml
# generated by nexus
```

### 10.3 OpenCode

**Writes:**
- `.opencode/commands/`
- `.opencode/config.json`

**Adds marker file:**
`.opencode/.nexus-managed`

---

## 11. Layout Modes

### 11.1 direct (default)

Write directly into expected tool directories.

**Pros:**
- Maximum compatibility
- Minimal complexity

### 11.2 generated

Generate into `.nexus/generated/` and symlink.

**Pros:**
- Clean repo root
- Atomic swap capability

---

## 12. Cleanup Strategy

### 12.1 owned-only (default)

Only remove artifacts that Nexus previously generated.

**Ownership markers:**
- `.claude/skills/.nexus-managed`
- `.mcp.json` with generator marker
- `.codex/config.toml` header
- `.opencode/.nexus-managed`

### 12.2 full (optional)

Remove entire managed directories.

---

## 13. Activation Lifecycle

On shell enter:

1. Compute desired state hash
2. If unchanged → exit
3. Resolve packs + imports
4. Validate enable lists
5. Compile Canonical Graph
6. Emit per-client outputs
7. Write state hash

---

## 14. State Hash

**Hash includes:**
- Pack IDs
- Import revisions
- Enable lists
- Clients
- Layout mode

**Stored in:** `.claude/.nexus-state`

**If unchanged → skip injection.**

## 18. Testing Strategy

### 18.1 Unit Tests

**Test:**
- Enable resolution
- Namespace formation
- Collision detection
- Canonical graph merge
- Emitters

### 18.2 Golden Tests

**Fixtures:**
```
fixtures/packs/*
fixtures/repos/*
```

**For each:**
1. Activate Nexus
2. Snapshot:
   - `.mcp.json`
   - `.codex/config.toml`
   - `.opencode/*`
   - `.claude/skills/*`
3. Diff against golden outputs

**Breakage = CI failure.**

### 18.3 Integration Tests

- Missing enabled item
- Collision case
- Missing env var
- Floating import disallowed
- State hash no-op

### 18.4 CI

Run:
```bash
nix flake check
```

**Checks include:**
- unit
- golden
- integration
