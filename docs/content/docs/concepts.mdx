## The core idea

You define AI tooling once (in a pack), enable it per repo, and Replix generates the client-native files your AI agent expects. No copy-paste, no drift.

---

## Pack

A pack is a versioned bundle of skills, commands, agents, hooks, and/or MCP server configs. You add packs to a repo, and Replix compiles them into files each AI client understands.

> **Packs are Replix's own spec.** No external pack registry exists yet — the reference packs (`starter`, `security`, `content`, `dataops`) live in Replix's own fixtures. [ClawHub](https://clawhub.com) publishes individual skills, not packs.

```bash
npx replix add github:myorg/ai-packs starter
```

The `starter` pack ships with:
- a `repo-status` **skill** — gives your AI context about the repo
- a `/review` **command** — slash command for code review
- a `security` **agent** — specialized security review mode
- a **MCP** server config for filesystem access

Packs live in git repos. You reference them by source URL and pack name.

---

## Skills

Skills are markdown files that inject context into your AI coding agent (Claude, OpenCode, Codex). They explain tools, conventions, or domain knowledge the agent should know about.

The `humanizer` skill (inside `content-pack`) might contain: "When writing user-facing copy, prefer short sentences and active voice. Avoid jargon."

After `replix` runs, the skill lands at:

```
.claude/skills/humanizer/SKILL.md     ← Claude Code reads this
.opencode/skills/humanizer/SKILL.md   ← OpenCode reads this
.agents/skills/humanizer/             ← Codex reads this
```

To get the `humanizer` skill, add the `content` pack:

```bash
npx replix add github:myorg/ai-packs content
```

---

## Commands

Slash commands your AI agent can invoke. Example: the `starter` pack ships a `/review` command that triggers a structured code review.

After `replix` runs:

```
.claude/commands/review.md      ← available as /review in Claude
.opencode/command/review.md     ← available in OpenCode
```

---

## Agents

Specialized AI modes. A pack can ship an agent definition that changes how the AI behaves for a specific workflow. The `security` pack ships a `red-team` agent for adversarial security review.

```
.claude/agents/red-team.md
.opencode/agent/red-team.md
```

---

## Hooks

Lifecycle triggers — run before/after tool calls, on commit, etc. Replix maps hook definitions to each client's native format automatically.

---

## MCP

MCP (Model Context Protocol) server configs. Define once in a pack, emit to `.mcp.json`, `opencode.json`, and Codex config automatically.

---

## Apply, Check, Lock

| Command | What it does |
|---|---|
| `replix` | Generates/updates client-native files from enabled packs |
| `replix check` | Detects drift between config and generated files (non-mutating) |
| `replix lock update` | Pins pack revisions + checksums into `replix.lock.json` |
| `replix doctor` | Diagnoses config health: missing vars, lock drift, pack readiness |
